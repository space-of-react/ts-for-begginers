# Тесты-самопроверка для заданий

Это курс про **типы** TypeScript, поэтому проверки в основном идут на уровне типов
(а не поведения программы). Мы используем [Vitest](https://vitest.dev/) в режиме
проверки типов (`typecheck`) + `expectTypeOf`, который **ловит даже `any`** —
обычный `tsc` этого не умеет.

## Как запускать

Одна команда на задание — та же, что и раньше:

```bash
npm run task:07
```

Одна команда `task:07` открывает **UI-дашборд в браузере**
([@vitest/ui](https://vitest.dev/guide/ui)) **и** одновременно печатает результат
**в терминал** — список проверок с галочками `✓` и крестами `×`, названия по-русски
(«тип Theme должен быть …»). Ученик правит `src/07-...проблема.ts`, сохраняет —
и статусы обновляются вживую и там, и там.

`✓` = решено верно, `×` = ещё нет. Пока задание не решено, оно **красное** — это нормально,
в этом и смысл: список показывает цель.

Проверить эталон: `npm run solution-07` прогоняет те же проверки против файла решения
(должны быть все зелёные).

> Отдельных команд `npm test` / `test:NN` намеренно нет — всё через `task:NN` / `solution-NN`.

## Как это устроено

Структура одного задания — три файла:

- `src/NN-...проблема.ts` — то, что редактирует ученик.
- `src/NN-...решение.ts` — эталон.
- `tests/NN.test.ts` — проверки (пишешь только его, импортит **проблему**).

Команды:

- `task:NN` → `vitest --ui tests/NN.test.ts` — тесты против **проблемы** (ученик).
- `solution-NN` → `vitest --ui tests/NN.solution.test.ts` — тесты против **решения** (автор).

Файл `tests/NN.solution.test.ts` **создаётся автоматически** из `tests/NN.test.ts`
(в нём `.проблема` заменена на `.решение`) при запуске `npm run play:generate`.
Руками его не трогай.

Внутри теста:

- Проверки типов: `expectTypeOf<...>().toEqualTypeOf<...>()` — сверяет тип с эталоном
  (ловит даже `any`).
- Проверки поведения (задания 22, 23, 24, где есть логика): обычный `expect(...)`.

## Как добавить тест для нового задания

1. Создай `tests/NN.test.ts` (NN — номер задания, как у файла в `src/`).
2. Импортируй из файла проблемы и опиши, каким должен стать тип/поведение:

   ```ts
   import { describe, test, expectTypeOf } from 'vitest';
   import type { MyType } from '../src/NN-название.проблема';

   describe('NN — название', () => {
     test('MyType должен быть ...', () => {
       expectTypeOf<MyType>().toEqualTypeOf</* эталон */>();
     });
   });
   ```

3. Запусти `npm run play:generate`. Он:
   - переключит `task:NN` на запуск твоего теста;
   - создаст `tests/NN.solution.test.ts` и переключит `solution-NN` на него.

   Так работает и для всех будущих заданий: добавил тройку
   «проблема + решение + `tests/NN.test.ts`», запустил `play:generate` — готово.

### Полезные проверки типов

| Что проверить | Как |
| --- | --- |
| Тип равен эталону | `expectTypeOf<T>().toEqualTypeOf<Эталон>()` |
| Тип параметра функции | `expectTypeOf(fn).parameter(0).toEqualTypeOf<string>()` |
| Тип возврата функции | `expectTypeOf(fn).returns.toEqualTypeOf<number>()` |
| Функцию можно вызвать без аргумента | `expectTypeOf(fn).toBeCallableWith()` |
| Поведение (runtime) | `expect(fn(...)).toBe(...)` |

> Важно: для пересечений (`A & B`) сравнивай именно с формой пересечения
> `toEqualTypeOf<A & B>()`, а не с «плоским» объектом — иначе `toEqualTypeOf`
> посчитает их разными (см. `tests/11.test.ts`).
